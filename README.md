# 自动打卡助手

个人使用的 Kotlin 原生 Android 应用，最低支持 Android 10（API 29）。原始版本针对 ColorOS 12.1 开发。默认每天 **上班 08:30、下班 18:00（手机本地时区，包含周末）** 分别唤醒屏幕并打开钉钉，识别极速打卡成功提示，写入本地日志后锁屏。两个时间都可在界面选择修改，并分别启停。

无密码锁屏、已登录钉钉、已开启极速打卡、已准备定位和考勤 Wi-Fi 是运行前提。本应用不负责登录、定位配置或验证钉钉服务器考勤记录。

已在用户连接的 **OPPO PCRM00 / Android 12 / ColorOS 12.1 / 钉钉 8.5.5** 上安装调试。已验证灭屏定时唤醒、启动钉钉、超时重试、写日志、锁屏及停止任务；改用系统闹钟类型后，1.0 版一次实测触发偏差为 77ms。1.1 版增加独立上下班时段，1.2 版增加 QQ 邮件通知和低电量提醒，1.3 版增加防移动监测，1.4 版支持独立自测和灵敏度选择，1.5 版增加可选的低频加速度兜底检测；完整验证记录见文末链接。真实成功提示识别及整夜待机仍待实际考勤场景验证。

## 在 Windows Android Studio 中打开

1. 选择 **Open**，打开本项目根目录 `D:\project\autoCheckin`，等待 Gradle 同步。
2. 在 **Settings → Build, Execution, Deployment → Build Tools → Gradle** 中使用 **JDK 17**。本机已有 `C:\Users\stone\.jdks\ms-17.0.16`。不要使用系统 Java 19 或本机 Studio 自带 JDK 25 来运行 Gradle 8.7。
3. SDK Manager 中确认 Android SDK Platform 35、Build Tools 35.0.0（AGP 也可能使用已有 34.0.0）、Platform Tools 已安装。
4. 本机已生成 `local.properties` 和本地 IDE JDK 配置。换目录或换电脑时用 Android Studio 重新生成 SDK 路径；本地文件不应提交。
5. 连接手机，开启开发者选项和 USB 调试，在手机上接受电脑 RSA 授权，选择 `app` 并点击 **Run**。

构建版本固定为 AGP 8.6.1、Gradle 8.7、Kotlin 2.0.21，编译/目标 SDK 35，最低 Android 10（API 29）。只使用平台 UI 和 API，测试使用 JUnit 4。

## 第一次设置

打开助手，依次完成界面上的权限设置：

| 设置 | 用途 |
| --- | --- |
| 精确闹钟 | Android 12+ 需授权“闹钟和提醒”；Android 10/11 无需单独授权 |
| 通知 | 显示运行状态和停止按钮；Android 13+ 需授权，并开启“打卡任务”通知渠道 |
| 电池优化豁免 | 减少待机限制；与厂商后台设置分别配置 |
| 无障碍服务 | 启用“自动打卡助手”，回到界面确认显示“已连接” |
| 设备管理员 | 仅请求“锁屏”，用于结束后调用系统锁屏 |

Android 13+ 侧载应用若不能启用无障碍，在应用详情右上角菜单中检查“允许受限设置”，然后返回无障碍设置。设备管理员启用后卸载前需先在系统安全设置中撤销。

ColorOS 12.1 上还需手动检查（具体菜单名称以实机为准）：

- **设置 → 应用管理 → 自动打卡助手**：允许自启动、关联启动；若有后台弹出界面选项，也需允许。
- **设置 → 电池 → 应用耗电管理**：允许自动打卡助手后台活动，不限制后台耗电。
- 在最近任务中锁定助手；检查钉钉本身的后台运行与定位设置。
- 关闭密码、图案、PIN 等安全锁屏。无密码的滑动锁屏使用系统解锁 API 处理。

界面会阻止在关键条件缺失时启用任务。运行前也会重新检查条件；运行中撤销权限会导致异常记录，系统直接杀进程时只能在下次进程启动后记录中断。强行停止应用后，需手动打开助手恢复闹钟。

## 测试与启用

“启用每日任务”是总开关；下面的“上班卡”和“下班卡”可分别启停，点击各自右侧时间按钮选择小时/分钟。总开关停用时仍可编辑时间，但不会登记闹钟。两个启用时段需至少间隔 3 分钟（包括跨午夜），给两次重试和锁屏留出时间。允许夜班配置，不要求“下班时间”晚于“上班时间”。

上班任务结束后，服务和 WakeLock 会退出，但下班闹钟已独立登记在系统中，因此会再次唤醒。两个任务的运行 ID、重试计数、日志标签分别独立；上班成功不会导致下班被跳过。升级时保留原总开关、上班时间和高级配置，并增加默认启用的 18:00 下班时段，清除旧单时段闹钟。

1. **测试启动钉钉**：只请求打开钉钉并写日志，不监测结果、不锁屏；打开钉钉本身仍可能触发真实极速打卡。
2. **测试完整流程**：先选择上班卡或下班卡，再立即执行整个流程，结束后锁屏。不会开启每日任务，也不会改变已安排的时间。标签不会修改钉钉自身的考勤规则，具体签到/签退由钉钉决定。
3. 将时间设为当前时间后 2–3 分钟，启用任务，返回桌面并手动灭屏，检查真正的后台闹钟唤醒。
4. 查看最近日志。确认 `START → ATTEMPT → LAUNCHED → SUCCESS → LOCKED`，并人工核对钉钉考勤记录。`LAUNCHED` 只表示已发出启动请求。
5. 调回上班 08:30、下班 18:00，再验证整夜待机和实际上下班考勤。

完整流程在每次尝试开始后最多等待 60 秒；第一次超时后重新打开钉钉一次，再等待最多 60 秒。不会强行停止钉钉或重复点击无限重试。12 秒内未完成唤醒/启动则记录异常并结束。

结束结果分为：

- `SUCCESS`：本次观察到与配置匹配的成功文字，并非直接查询考勤服务器。
- `UNCONFIRMED`：两次等待都没有识别成功；可能已打卡但提示未暴露给无障碍，必须人工核对。
- `ERROR`：权限、唤醒、启动等异常。
- `CANCELLED`：从界面或运行通知停止本次任务，不主动锁屏。
- `INTERRUPTED`：进程或服务中断，不能保证当时执行了锁屏。

成功、未确认及唤醒后的异常都会尝试锁屏。`LOCKED`/`LOCK_ERROR` 与打卡结果分别记录，运行日志包含“上班卡/下班卡”标签。停用总开关会取消两个闹钟并停止当前任务，不主动锁屏；单独停用一个时段只取消该时段，如该时段正在运行也会停止，不影响另一个时段。

## 高级识别与点击

默认只打开钉钉并观察，不自动点击。成功关键词默认“打卡成功”，可按实际提示修改，每行一个。仅处理钉钉包名的运行期新事件，结合可见节点、文字、contentDescription 和可读取的 Toast/通知。不会截图、OCR、上传页面内容或把整个节点树写入日志。

成功判定采用包含关键词的短行文本，并排除明显失败或帮助文案；上班任务排除含“下班”的行，下班任务排除含“上班”的行，以免明确的另一班次结果被误认。通用“打卡成功”没有班次信息，仍按当前任务记录；这不是钉钉服务器确认。没有识别成功时只记录“未确认”，不能推断为考勤失败。上下班共用高级识别与点击配置。

必要时启用高级点击，填写**准确文字**、**contentDescription** 或**完整 resource-id**。启动钉钉 8 秒后按这个顺序查找可见节点，尝试点击该节点或最近的可点击父节点。每次尝试最多执行一个动作；这是单步兜底，不是多页面考勤导航脚本。

节点无法点击时，只有明确打开“允许坐标兜底”才使用保存的 X/Y。单位是屏幕像素，原点是屏幕左上角，包括状态栏；可通过开发者选项“指针位置”读取。保存时绑定当前屏幕尺寸与方向。应用不在钉钉前台、分辨率/旋转方向变化或坐标越界时跳过，不自动缩放。

全屏节点中已有的历史成功文字仍可能造成误判，帮助文案及明显失败文案会尽量排除。应选择本机钉钉实际使用的明确成功提示，首次配置必须人工核对；不把本工具日志视为服务器考勤凭据。

## 调度、日志与实现

- 两个独立 `AlarmManager.setAlarmClock()` 精确唤醒闹钟逐日安排，使用不同的 PendingIntent 标识和各自的预定时间；触发时只安排该时段次日闹钟。系统显示最近一次闹钟，点击可返回助手。实测 ColorOS 12.1 会合并普通 `setExactAndAllowWhileIdle`，因此使用用户可见的闹钟类型。重启、升级应用、修改时间/时区、恢复精确闹钟权限后重新计算两个时段。闹钟延迟超过 5 分钟则记 `MISSED`，不补执行过去任务；`ALARM` 日志包含时段与实际触发偏差。
- 前台服务只在任务期间运行，使用 `specialUse` 类型；无障碍服务通过系统绑定。部分 WakeLock 保持 CPU，限时屏幕 WakeLock 在观察期间保持显示，由唤醒 Activity 点亮屏幕并解除非安全锁屏。结束时释放两种锁；即使异常，WakeLock 也会在 150 秒自动到期。
- 每次运行有独立 ID；先安排下次闹钟再执行本次，忽略旧闹钟和并发运行。配置在开始时读取，运行中不会切换规则。
- 日志为私有目录 `files/logs/YYYY-MM-DD.jsonl`，写入时清理 30 天以前的文件，界面最多显示最近 500 条。包含阶段、时间、结果和最多 120 字的成功证据，不包含完整页面或聊天记录。卸载后配置及日志被删除，备份已禁用。
- 主进程内完成所有组件协作；邮件使用联网权限和系统 JobScheduler，没有自建服务端、WorkManager 或常驻轮询服务。

### 待机耗电

空闲时不持有 WakeLock，不运行打卡前台服务，也不订阅钉钉无障碍事件；无障碍服务仍由系统绑定，以便闹钟触发后后台唤醒。设置页面只在可见时检查权限状态。任务期间订阅事件，不轮询钉钉页面；屏幕锁允许屏幕变暗，成功后立即结束，两次超时约 120 秒后结束，每把 WakeLock 都有 150 秒硬超时。默认每天两次任务，正常两次超时合计约亮屏 4 分钟，不包括人工使用。钉钉、定位、Wi-Fi 和厂商后台策略仍会影响整机电量，尚未进行整夜电耗测量。

邮件只在产生事件且队列非空时请求网络任务，不维持 SMTP 长连接，也不定期唤醒发心跳。每轮发送最多处理 3 封，45 秒后关闭连接，失败后系统从 5 分钟起指数退避；锁屏不等待邮件。低电量通过系统电池广播触发，不启动轮询或额外常驻服务。

## QQ 邮件通知

在主界面打开“邮件通知”，填写 QQ 发信地址、收件地址和 SMTP 授权码，开启邮件通知后保存。可使用同一个 QQ 邮箱发给自己。服务固定为 **smtp.qq.com:465，隐式 TLS**，校验系统信任的服务器证书和域名，不允许明文或忽略证书。

- 授权码使用 Android Keystore 管理的 AES-GCM 密钥加密，保存在手机私有目录；不放入 APK、源码、日志或备份。设置页防截图、禁止密码自动填充/页面状态保存，保存后清空输入框；留空保留原授权码。更换发信账号必须输入新的授权码。
- “保存并发送测试邮件”只发配置测试，不触发打卡。“保存并重试待发邮件”可在修复授权码或网络后重新请求发送。配置页显示待发数量和最近发送状态。
- 每次打卡成功、未确认、异常或手动取消均入队一封结果邮件，包含上下班标签、运行 ID、事件时间、识别结果及锁屏结果。捕获到的服务启动失败、错过任务也会通知。邮件中的“成功”只表示读取到匹配提示，不是服务器考勤确认。
- 服务意外销毁时尽力报告中断；若系统直接杀死进程，等下次应用启动才读取遗留运行状态并补报，不能即时发现。正常任务完成后服务退出不算故障。
- 低电量提醒可独立关闭：未连接电源且电量 ≤20% 提醒一次，恢复到 ≥25% 后重新允许提醒。进程不在时依赖系统低电量广播，阈值及投递可能因系统而异；不能保证耗尽关机前邮件必达。
- 私有文件 `files/mail_queue.json` 持久保存待发消息。系统有网络时执行发送，失败最多尝试 5 次；超过 24 小时的消息在下一次处理队列时丢弃。队列上限 100 封；认证失败暂停重试，重新保存配置后恢复。可手动清空队列。关闭邮件暂停发送；再次开启后处理未过期消息。修改收件地址会影响已有待发邮件。
- `MAIL_QUEUED` 为排队，`MAIL_SENT` 表示 QQ SMTP 已接受，不等于收件箱已送达；请留意垃圾邮件。`MAIL_RETRY` 为暂时失败，`MAIL_BLOCKED` 为需要修复配置或 TLS 校验问题，`MAIL_REJECTED` 为服务器拒收，`MAIL_EXPIRED` 为超过重试次数或时限。网络在服务器接收后中断可能引起重复邮件，可用相同 Message-ID/运行 ID 识别。

手机关机、完全离线或被强行停止后无法自行发信。本版未接入外部监测，因此不承诺这些情况下有即时提醒；未来需要第三方服务按预定时间检查报告是否缺失。

## 防移动监测

**1.4 自测入口**：任何状态下都可点“开始自测／重新开始自测”，立即清除当前限频，10 秒后布防，自测触发后仅暂停 15 秒；邮件标题注明“防移动自测”。完成后点“退出自测，恢复正式监测”，重新倒计时 10 秒并使用正式 60 秒限频。单纯返回主界面不退出自测，状态页和通知始终显示模式；重启自动回到正式模式。显式重新自测会绕过限频，请避免反复点击造成多封测试邮件。

**灵敏度**：默认“灵敏”，显著运动或倾斜任意一个事件均触发；“稳健”只启用显著运动，减少误报。设置立即生效，不清除限频，也不改变布防时间。灵敏档等同于上一版的双传感器行为，不意味着能调低芯片阈值；硬件不开放阈值配置。两档在关闭下面的加速度选项时都不新增加速度/陀螺仪采样或 WakeLock，不能保证捕捉细微轻碰。

**低频加速度检测（1.5 可选开关）**：默认**关闭**并持久保存，与灵敏度档位相互独立，取消勾选后**绝不注册加速度计**。用于某些机器没有公开倾斜传感器、或厂商显著运动算法不被原地晃动稳定触发时的兜底。

- 开启后原有显著运动/倾斜行为不变，额外以 `samplingPeriodUs=1000000`（约 **1 Hz**）注册**非唤醒型**加速度计（`TYPE_ACCELEROMETER`，含重力），不常驻持有 CPU WakeLock（`dumpsys sensorservice` 实测 `WakeLockRefCount 0`），也不使用每 10 秒一次的 exact alarm（Doze 会限频且更耗电）。
- **实际速率由系统/HAL 决定**：荣耀 X10（Android 10）把该请求收到 `samplingPeriod=200000us`（约 5 Hz），并未按 1 Hz 降频。因此“连续两次”在真机上约为 0.4 秒而不是 2 秒，判定更灵敏、也更容易被瞬时抖动触发。本机实测无法配置更慢的速率；如需更长的确认窗口，应在服务层对采样抽稀，本轮未做。
- 判定规则：首次采样建立重力方向基线；此后重力方向相对基线偏转 **≥30°且连续两次采样**命中，判定为“加速度计姿态变化”；单次动态加速度相对 1 g 的偏差 **≥3 m/s²**，判定为“加速度计明显加速”。静止噪声通常只有 1～2°，不会触发。
- 触发后完全复用现有 `movement()` 流程：先持久记录限频、再入邮件队列，正式 60 秒／自测 15 秒限频，邮件与日志来源分别标注“加速度计姿态变化”“加速度计明显加速”。布防、暂停、灵敏度重配、限频到期重新注册时都会清空基线，重新以本次布防后的第一次采样建立基线。
- 状态页与常驻通知都显示开关状态、本机硬件名称和本次实际注册结果（`已注册`/`开关关闭`/`本机不支持`/`未注册`）。
- **限制**：加速度计是非唤醒传感器，**手机深度休眠（Doze）时不保证有采样**，此时兜底属于 best-effort，检测仍以唤醒传感器为准；增加约每秒一次采样，会有少量额外耗电（未做整夜对比测量）。它只是低频兜底，不能保证捕捉极慢平移、细微轻碰或休眠期间的移动。

主界面打开“防移动监测”，先确认邮件测试能收到，再点“开启监测”。首次安装默认关闭，需要显式布防。开启后留出 **10 秒** 把手机放进盒子；状态显示“已布防”后，手机被拿起、翻转或明显搬动时尝试发送“手机疑似被移动”的邮件，包含事件时间、传感器类型和电量。不响铃、不拍照、不点亮屏幕。

- 默认仅使用本机 **sns_smd Wakeup 显著运动传感器**和 **pick_up_motion Wakeup 倾斜传感器**。后者通过公开的传感器枚举 API 按 `android.sensor.tilt_detector` 查找，不调用隐藏接口。优先注册两者，若只有一种可用则显示实际注册状态；两种均不可用则停止并报告异常，不退回高频加速度/陀螺仪采样。只有显式勾选低频加速度检测时才会额外注册非唤醒加速度计。
- 监测使用独立 `specialUse` 前台服务和常驻通知，不持有 WakeLock、不轮询传感器。显著运动是一次性硬件触发；倾斜是硬件事件。倒计时结束和限频结束分别使用单次系统唤醒闹钟，页面关闭后没有每秒刷新循环。
- 第一次触发先持久记录限频状态再入邮件队列，两种传感器同时触发也只提醒一次。随后**暂停检测 60 秒**，到期自动重新注册传感器。这段时间不积累移动次数、不重复发信。正式模式连续移动每 60 秒最多一封；快速暂停再开启也不绕过同次开机的限频。
- 点击页面或通知里的“暂停监测”会撤销传感器、恢复闹钟和前台服务；已有待发移动邮件保留。自己取出手机前先暂停。没有锁屏密码，因此他人也能操作暂停；此功能是异常移动提醒，不是防拆或防盗锁。
- 上下班任务与防移动监测相互独立，打卡结束不停止监测，监测布防也不取消打卡闹钟。屏幕唤醒、锁屏不是运动信号；真实晃动、盒子被碰撞可能触发。
- 重启/覆盖安装后，对之前启用的监测尝试恢复；重启后恢复正式模式，重新给 10 秒放置时间。服务被系统杀死时使用系统粘性恢复机制，但可能有空窗，不保证恢复时限。强行停止后需手动打开本应用。冷启动不额外创建重复监测进程。
- 手机 Wi-Fi 可用时邮件由现有队列发送；SMTP 或系统后台策略可能造成延迟。ColorOS 灭屏时也可能延迟倒计时/限频恢复，需以“已布防”状态为准。传感器不能保证发现极慢平移或每次轻碰，不能据此证明手机被盗。

建议实测：静置布防后灭屏，拿起并翻转，再连盒子移动；核对 `MOTION_DETECTED → MAIL_QUEUED → MAIL_SENT` 与收件箱。限频期继续移动不应多发；正式模式等 60 秒、自测模式等 15 秒且显示已布防后再次测试。长期耗电需在实际静置环境下比较，不能从短时测试推断整夜电量。

低频加速度检测另测：勾选后等状态显示“加速度计（兜底）：已注册”，拿起或翻转手机，应出现 `MOTION_DETECTED` 且来源为“加速度计姿态变化／加速度计明显加速”；取消勾选后 `adb shell dumpsys sensorservice` 中本应用应只剩 `significant Motion 0x0000000f`，不再出现 `0x00000000`（加速度计）。

Debug 版可用 `adb shell run-as com.personal.autocheckin ls files/logs` 查看日志文件名，再用 `adb shell run-as com.personal.autocheckin cat files/logs/实际日期.jsonl` 读取对应文件。查看闹钟可用 `adb shell dumpsys alarm`，搜索 `com.personal.autocheckin`。
