# Android 10 compatibility implementation plan

> Execute inline with executing-plans; verify with lint, unit tests and device smoke checks.

Goal: Build and install this app on the user's Honor X10 / Android 10 (API 29).
Architecture: Keep platform UI and existing behavior. Guard Android 11/12 APIs and use Android 10 equivalents. Keep compile/target SDK 35; lower only minimum SDK to 29.
Spec: User request in this session; existing APK minSdk 31 exceeds device SDK 29.

## Constraints and review focus

- Preserve original clone and existing app data; no uninstall, account setup or actual attendance actions.
- Exact alarm access must return true before API 31 without invoking absent methods.
- Main, mail and motion pages must render on API 29, including system bars and keyboard.
- Advanced coordinates must use real display size and rotation on API 29, retaining API 30+ behavior.
- Preserve existing API 33/34 notification, receiver and foreground-service guards.
- No push or merge is required; APK and patch are deliverables.

## Steps

- [x] Prepare JDK 17, SDK 35, build-tools 34 and Gradle 8.7 under parent toolchain directory.
- [x] Run baseline unit suite. Lower minSdk to 29 and run lintDebug to obtain failing NewApi diagnostics before runtime fixes.
- [x] Guard Permissions.exact at API 31 and exact-alarm settings button; old OS explains permission is unnecessary.
- [x] Add shared platform compatibility helpers for insets (API 30 getInsets / API 29 systemWindowInsets plus cutout) and maximum display bounds (API 30 maximumWindowMetrics / API 29 defaultDisplay.getRealSize).
- [x] Use helpers from three activities and accessibility coordinate validation; use defaultDisplay.rotation on old API.
- [x] Run testDebugUnitTest, lintDebug and assembleDebug; resolve compatibility findings.
- [x] Install via non-streaming adb, launch main, check process and crash logs; do not enable automatic tasks.
- [ ] Mail/motion/advanced pages and keyboard layout: deferred to avoid interfering with user permission setup; explicitly unverified.
- [x] Export APK, diff and verification report; report remaining permission setup separately from installation success.

## Rulings / evidence

- Native inline implementation is appropriate for this single bounded fix; user's install request authorizes local build and install.
- Original clone's tracked differences are CRLF only (`git diff --ignore-space-at-eol --stat` empty); linked worktree preserves them.
- Streaming original APK twice caused USB transport loss without package manager error; switch installation transport after build.

## Final verification

Build, 25 unit tests, lint, signature, install and main launch passed. Independent review found no concrete defect. Mail/motion/advanced and keyboard runtime checks stopped when the user appeared to be configuring administrator permissions; these remain explicitly unverified in ../artifacts/verification-android10.md. No actual attendance actions were triggered. Native Windows ADB solved USBIP outbound transfer failures; WSL attachment restored afterward.
